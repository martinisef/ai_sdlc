## Tools
| Role | Tool | Notes |
|---|---|---|
| Dependencies | **Bundler** (`Gemfile.lock` committed) | Ruby version in `.ruby-version` |
| Formatting and lint | **RuboCop** (`rubocop-rails-omakase` or the team's `.rubocop.yml`) | |
| Tests | **Minitest** (`bin/rails test`) or **RSpec** if the repo has `spec/` | `sdlc init` picks `bundle exec rspec` when it finds `spec/` or `.rspec` |
| API (project_type = api) | Rails (`--api` if there is no frontend) | migrations in `db/migrate`, schema in `db/schema.rb` |

## Makefile
```make
.PHONY: build test lint format run
build:  ; bin/rails zeitwerk:check
test:   ; bin/rails test
lint:   ; bundle exec rubocop
format: ; bundle exec rubocop -a
run:    ; bin/rails server
```
With RSpec: `test: ; bundle exec rspec`.
If the project is empty: `rails new <app> --database=postgresql` (add `--api` for an API).

## sdlc.json
```json
"stack": { "language": "ruby", "package_manager": "bundler", "project_type": "<api|web|library>" },
"format_on_edit": { "*.rb": "bundle exec rubocop -a {file}" },
"test_globs": ["test/**", "spec/**"],
"protected_paths": ["db/schema.rb", "db/structure.sql"],
"append_only_paths": ["db/migrate/**"]
```
Migrations are append-only: `bin/rails generate migration` creates new ones, but an applied migration is never edited; it is corrected with a new one. `db/schema.rb` is generated by `bin/rails db:migrate` and is never edited by hand, so the commit that adds a migration together with the regenerated schema needs a code owner (`SDLC_OVERRIDE=protected-paths git commit …`). If the team prefers the agent to commit migrations on its own, move `db/schema.rb` out of `protected_paths`.

## Conventions for CLAUDE.md (seeds)
- Business logic outside controllers (models or service objects).
- No N+1 queries: `includes` when iterating associations; every new query has an index.
- Every migration is reversible (`change`, or `up` with a `down`).
- No new gem without asking.
